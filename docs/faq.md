# Frequently asked questions

## How do I run the settings of the paper?

`preset="paper_151673"`, `"paper_integration_vertical"`, `"paper_integration_horizontal"`,
`"paper_mouse_olfactory_stereo"`, `"paper_starmap"`, `"paper_merfish"` and
`"paper_slideseq_olfactory"` replicate the per-dataset settings of the paper (float64, seeds, τ,
epochs, image PCs, pseudo-labels); `staig.datasets.load_dlpfc("151673", download=True)` gives the data
with the released histology features. The [reproduction page](tutorials/reproducing_the_paper.md)
lists the commands. Training is stochastic by design: seeds are fixed and recorded, `n_graph_samples`
resamples the augmented graphs, and `run(n_seeds=...)` returns a consensus labelling over several
seeds, which is the recommended way to obtain stable domains.

## Do I need scGeneClust, PyWGCNA, SpatialDE or R?

None is required for the v2 core pipeline. Python GMM is the default clusterer,
BatchKL and (i/c)LISI are implemented in pure Python (no R, no harmonypy). R plus rpy2 and
R's `mclust` are only needed if you explicitly choose `method="mclust"` (or
`cluster_method="mclust"` in `run`). Image extraction needs `[image]`;
Leiden needs `[cluster]` (Louvain additionally needs the `louvain` package, which has no wheels on some platforms). Follow [installation](installation.md) and
avoid mixing the v1 `requirements.txt` workflow with v2.

## Where are the datasets, and can I download only one slice?

Use [Zenodo record 14231773](https://zenodo.org/records/14231773). `STAIG_DATA`
points to the unpacked `Dataset` folder, not its parent. The downloader reads
the ZIP directory and selected members through HTTP Range requests:

```python
import os
from staig import datasets

datasets.download_dataset(
    root=os.getenv("STAIG_DATA"), members=["DLPFC/151673"],
    include_full_image=False,
)
adata = datasets.load_dlpfc("151673", root=os.getenv("STAIG_DATA"))
```

Omitting the full-resolution image keeps the released embeddings and smaller
display images; it prevents fresh full-resolution image extraction until that
TIFF is downloaded. Use `datasets.list_members()` to inspect exact member names.
Existing files of the expected size are skipped. New downloads are CRC-checked;
size-based resumption does not revalidate an existing file's CRC. Use
`overwrite=True` only when you intend to replace selected files. A loader's
`download=True` does not repair an already-existing incomplete slice folder.

## Where are the zebrafish melanoma data?

The original GEO samples are
[GSM4838131 (Visium-A)](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSM4838131)
and [GSM4838132 (Visium-B)](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSM4838132),
in [GSE159709](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE159709).
The curated Zenodo archive includes them under `v10x/`, in folders
`GSM4838131_Visium_A` and `GSM4838132_Visium_B`. The following loads one; availability
of labels, pretrained embeddings and full-resolution images varies by folder:

```python
import os
from staig import datasets

zebrafish = datasets.load_visium(
    "GSM4838131_Visium_A", root=os.getenv("STAIG_DATA"), download=True,
    labels=None, image_features=None,
)
```

See [paper Figure 7](https://www.nature.com/articles/s41467-025-56276-0/figures/7)
for the reported melanoma analysis.

## Can I use Visium HD, CosMx or another platform?

Yes, directly from the platform's output: `staig.run("path/to/outs")` or `staig run path/to/outs`
reads Space Ranger (Visium and Visium HD bins or segmented cells), Xenium, MERSCOPE, CosMx/AtoMx
flat files, SAW `.gef`/`.gem` (Stereo-seq), Slide-seq / Curio Seeker, seqFISH and generic counts +
coordinates tables, removes control probes and empty cells and applies the platform's preprocessing.
`staig inspect path` shows what would be read. The layouts, defaults and the vendor sample files
each reader was validated on are listed in [Input formats](input_formats.md). Presets are starting
configurations. There is no end-to-end image pipeline for non-Visium images; supply
aligned external features through the [custom-feature API](tutorials/custom_image_features.md).
Large HD datasets need the [memory guidance](tutorials/large_datasets.md).

## Where does `filtered_feature_bc_matrix.h5` come from?

It is a Space Ranger filtered feature/barcode count matrix supplied by the
original studies, not an output generated by STAIG. Original dataset sources
are listed in the paper's Supplementary Tables S1–S2 and
[data availability statement](https://www.nature.com/articles/s41467-025-56276-0#data-availability).
The accompanying `spatial/` files supply coordinates, image scaling and display
images. Keep the matrix and spatial files from the same sample together. A
pre-normalised h5ad is a different input and should not be renamed to this H5
filename.
